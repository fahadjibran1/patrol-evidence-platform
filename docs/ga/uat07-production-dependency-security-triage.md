The `npm audit` high counts for `whatsapp-web.js`, Puppeteer, Puppeteer-core and `@puppeteer/browsers` are *derived from the same vulnerable `extract-zip` chain*, not four independent exploit mechanisms. Root `brace-expansion` 1.1.12 and the server/build-only packages are not in the Windows payload. `ws` is loaded on Puppeteer import; `extract-zip` and `ip-address` are not loaded on that import. PatrolSafe's helper creates `LocalAuth`, not `RemoteAuth`; the latter is where `whatsapp-web.js` optionally requires `archiver`.

### Exposure classification

- **A — shipped/runtime relevant:** `ws` is loaded by Puppeteer in the production helper. Its vulnerable WebSocket parser is relevant to the local browser-control channel, although exploitation needs hostile frames at that channel.
- **B — shipped, vulnerable operation not practically reached in the reviewed workflow:** `extract-zip`, the derived Puppeteer/WhatsApp package findings, `ip-address`, `glob`, `brace-expansion`, `js-yaml`, and `lodash`. These remain genuine vulnerable versions in the payload; no finding is dismissed as a false positive.
- **C — not shipped in the Windows desktop payload:** `tar`, `@mapbox/node-pre-gyp`, `bcrypt`, `nodemailer`. These are not necessarily development-only for Vesoft as a whole: bcrypt and nodemailer belong to the separate licence-API workspace and need their own deployment review.
- **D — proven false/non-applicable advisory:** none.

Registry-verified compatible floor versions are `ws` 8.21.0, `ip-address` 10.3.1, `glob` 10.5.0, `brace-expansion` 1.1.18/2.1.4, root `js-yaml` 4.3.2, and `lodash` 4.18.0. These are *options*, not installed fixes. `extract-zip` has no patched release; the registry has no 2.13.3 `@puppeteer/browsers` or 24.43.2 Puppeteer. The licence-API audit suggests bcrypt 6.0.0 and nodemailer 10.0.10 as major-version fixes. A tar version above the reported `<=7.5.20` affected range exists, but the current 6.x transitive chain cannot be upgraded mechanically.

## Controlled decision

No broad `npm audit fix`, force upgrade, Puppeteer major override, WhatsApp downgrade, or package pruning is approved here. The `extract-zip` chain has no patched same-line release and the current WhatsApp package pins Puppeteer to an affected version. That makes complete elimination of desktop high findings a **review/recertification decision**, not a safe mechanical patch. Targeted patch updates (`ws`, `ip-address`, `glob`, `brace-expansion`, root `js-yaml`) can be prepared in a separately authorised package-change step with a new unsigned payload and live WhatsApp/Edge compatibility testing. Until then the existing signed v1.0.2 RC and its 403 shipped instances / 361 unique package-version records remain unchanged.

The accepted GA-UAT-07 UI polish only reorders discovered groups: available, mapped, then paused/review-required; it does not alter mapping semantics. No production dependency version, licence notice, LGPL component, or compliance-source archive has changed. If package versions later change, regenerate the inventory and notices and reassess LGPL/special licences before signing.
